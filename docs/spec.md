# 规范重构与界面重做

状态：代码重构、界面重做与自动验证完成，真实环境验收待完成。用户已明确授权提交并推送当前成果。

## 目标与范围

按既有 Java 项目的职责边界整理 Python 后端，使用 Python / FastAPI 自身的实现方式。完整重做前端布局、导航、视觉和状态反馈，保留已有能力：

- 账号注册、登录、退出，图片上传、素材库和编辑会话。
- 文生图、候选图采用，AI 对话、计划确认 / 取消 / 重试，任务进度。
- 画布缩放和平移、裁剪、调色、图层变换、文字、选区、撤销 / 重做及前后对比。
- 营销图、投放尺寸、批量处理和压缩包导出。

## 项目规范与兼容边界

| 职责 | 本项目 | 对应 Java 概念 |
|---|---|---|
| HTTP 入口 | routers：绑定参数、登录用户、调用服务、返回响应 | Controller |
| 请求与响应 | schemas：Pydantic 输入校验、中文字段说明及响应视图 | DTO / VO |
| 业务 | services：归属校验、业务规则、事务边界、任务编排 | Service |
| 复用查询 | repositories：提取编辑历史等复用查询，不提交事务 | Mapper / Repository |
| 持久化实体 | models：SQLAlchemy 实体及数据库约束 | Entity |
| 异常 | exceptions + error_handlers：业务异常与 HTTP 映射分离 | BusinessException / GlobalExceptionHandler |

- 保留 Python / FastAPI / SQLAlchemy / PostgreSQL / UUID；保留 Redis、对象存储、Worker 和 Agent。
- 保留 React / TypeScript / Konva，不迁移 Vue。前端样式按 `design.md`。
- 保留原 REST 路径、成功响应对象、HTTP 状态、JWT HttpOnly Cookie；业务和字段校验错误统一为 `{detail, code}`。
- SSE 和下载维持原协议。配置沿用现有 `app/config.py` 与已有环境变量机制。
- 本轮没有数据库结构迁移。业务变更须经过服务层，不能把 Java 接口 / 实现类机械搬到 Python。

## 已处理问题

1. 用户名先去空格再校验长度；UTF-8 密码字节数符合 BCrypt 限制。
2. 修改标题和当前图片先完成资源归属校验，一次提交，失败不会提前保存标题。
3. 业务异常统一映射；上传、选区、生成、批量的业务入口下移至 Service。
4. 34 个 HTTP 接口补中文用途和权限说明；DTO / VO 字段补含义和必要示例。
5. 共享画布服务脱离工具注册表，消除选区相关循环导入；阻塞密码计算、存储读取和画布合成移出事件循环。
6. 素材库的未归组素材按真实会话关联查询；多点选区编号连续；健康检查只读；生产环境支持前端深层路由刷新。
7. 默认测试与外部服务隔离；集成测试需显式指定独立资源，只清理本次创建的精确用户名。
8. 前端拆分 types、service/api、request，统一上传和下载错误，开启严格类型检查和页面懒加载。
9. 画布、文字、变换、裁剪、调色、属性、营销与批量组件按职责拆分。
10. 列表和任务区分加载、空、错误及重试；登录错误不会全部当作未登录；多文件上传保留全部结果；任务进度只平滑展示服务端报告值，最终快照覆盖断线前的旧进度与结果。

## 页面与视觉

首页为工具入口；创作页为生成 / 上传与最近素材；编辑器为画布 + AI 对话 + 属性；交付页为营销 / 尺寸 / 下载；批量页为素材选择 + 处理步骤 + 最近任务。手机使用底部导航和编辑面板切换。

所有配色、圆角、间距、文字和动画遵循 `design.md`。默认界面不展示实现细节或虚构统计。测试数据仅存在于测试目录。

- 后端：在 `backend` 执行 `uv run pytest -q`、`uv run ruff check app tests`、`uv run ruff format --check app tests`。
- 前端：在 `frontend` 执行 `npm run type-check`、`npm run lint`、`npm test`、`npm run build`、`npm run format:check`、`npm run test:e2e`。
- 流程测试仅启动自己的 5175 前端，拦截 API / SSE，不连接真实后端；截图自查覆盖 1280px / 390px、正常 / 空 / 错误。
- 集成测试保留在 `backend/tests/integration`。需独立测试数据库（名称 `_test` 结尾）、测试桶（`-test` 结尾）、非 0 的独立 Redis 库，并显式设置 `TEST_DATABASE_URL`、`TEST_REDIS_URL`、`TEST_S3_ENDPOINT`、`TEST_S3_BUCKET` 后运行 `uv run pytest --integration tests/integration`。
- 真正的模型调用、PostgreSQL / Redis / 对象存储联调由用户启动服务后验收；本轮自动验证不代替这一部分。

## 模板内容要求

- 第一方源码、文档、页面元信息和发布内容不得含原作者或第三方的推广、引流链接、宣传图片、二维码及追踪脚本。现有营销图生成功能与用户业务素材继续保留。
- `scripts/check-content.mjs` 扫描包括隐藏文件在内的模板内容；检测禁止词及其常见编码形式、未批准的外部地址，并验证已检查素材的 SHA-256。第三方依赖目录、Git 元数据、本地配置和运行缓存不作为第一方内容扫描；锁文件仍检查禁止词，依赖许可证不修改。
- `npm run check:content` 可单独检查；`npm run build` 在编译前检查模板、编译后检查全部 dist。Docker 使用相同构建命令，内容检查失败即停止构建。图片不能仅靠关键词判断，新增或变更图片必须先看实际内容再更新清单。
- 原推广名称只存在于 `scripts/content-policy.json` 的检测规则中；规则文件不参与前端打包，若被复制进发布包也会触发检查。允许的技术链接采用完整地址清单，不按整个域名放行。
- 浏览器内容检查使用生产构建产物，覆盖 1280px / 390px、公开页及业务页面的正常 / 空 / 错误状态；检查渲染后的内容、链接、嵌入元素和实际外联请求。API / SSE 全部模拟，不连接真实服务。
- 当前 3 个站点图标及 4 张评测图片已逐个查看并检查元信息，无推广内容；源码和发布包检查通过。Docker Compose 配置校验通过，本轮未启动 Docker 或执行镜像构建。
